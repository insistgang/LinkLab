## 2. Inference 指标设计

### 2.1 意图识别

| 测试集 | 样本量建议 | 目标 |
|---|---:|---|
| OCR/读文字 | 10 | 识别为 `ocr_text` |
| 场景描述 | 10 | 识别为 `scene_describe` |
| 物体识别 | 10 | 识别为 `object_identify` |
| 颜色识别 | 10 | 识别为 `color_identify` |
| 金额识别 | 10 | 识别为 `money_identify` |
| 翻译转述 | 10 | 识别为 `translate_or_relay` |
| 导航/导诊 | 10 | 识别为 `navigation_guide` 或转人工 |
| 药品确认 | 10 | 识别为 `medicine_check`，必要时建议人工确认 |
| 紧急求助 | 10 | 识别为 `emergency` 并进入 SOS |

指标：

```text
intent_accuracy = correct_intent_count / total_samples
目标：>= 85%
```

### 2.2 紧急检测

样本分组：

- 紧急样本：救命、迷路、摔倒、出血、着火、被困、呼吸困难、突然看不见等。
- 非紧急样本：药盒怎么读、帮我看路牌、这是什么颜色、附近公交站在哪里等。

指标：

```text
emergency_recall = emergency_true_positive / all_real_emergency
false_alarm_rate = non_emergency_false_positive / all_non_emergency
目标：召回率 >= 95%，误报率 <= 2%
```

### 2.3 决策动作

Agent 不只输出答案，还输出下一步动作：

| next_action | 应用场景 |
|---|---|
| `answer` | AI 可以直接解决 |
| `ask_followup` | 信息不足，需要追问 |
| `match_volunteer` | 低置信、复杂需求、现实行动需求 |
| `trigger_sos` | 紧急意图 |
| `show_fallback` | 服务不可用时给出安全降级 |

指标：

```text
action_accuracy = correct_action_count / total_samples
目标：>= 85%
```

## 3. 性能指标

| 指标 | 测量方法 | 目标 |
|---|---|---:|
| 首次可见响应时间 | 提交输入到出现“AI 正在分析” | <= 0.5s |
| AI 完整响应时间 | 提交输入到展示答案 | <= 3s |
| 匹配计算耗时 | 50 人 Demo 池 Top 5 排序 | <= 500ms |
| Demo Call 建立时间 | 匹配成功到通话页已接通 | <= 5s |
| SOS 触发反馈 | 点击 SOS 到撤销窗口显示 | <= 1s |

## 5. 和基线方案对比

| 方案 | 处理方式 | 风险 |
|---|---|---|
| 普通聊天机器人 | 直接给文本答案 | 低置信或高风险场景缺少兜底 |
| 单点 OCR 工具 | 只读文字 | 不能判断是否需要志愿者或 SOS |
| 人工求助平台 | 用户直接发请求 | 需求不标准、响应慢、志愿者负担高 |
| LinkAble | AI 先结构化需求，再分流到答案/志愿者/SOS | 需要持续优化意图识别和匹配策略 |

## 6. 风险与降级

| 风险 | 降级策略 |
|---|---|
| 外部 AI API 不可用 | 默认 DemoMode / 本地确定性响应 |
| OCR/视觉识别不确定 | 提示不确定并转人工确认 |
| 医疗、药品、导航高风险 | 不做最终判断，建议真人或专业人员确认 |
| 志愿者无人接单 | 进入 expired，提示留言或稍后再试 |
| SOS 误触 | 10 秒撤销窗口 |
| 真实 WebRTC 不稳定 | Demo Call 保证比赛闭环 |
