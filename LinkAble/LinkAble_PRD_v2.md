## 0. 一句话定义

**LinkAble 是一套基于边缘智能的无障碍辅助通行感知系统，面向视障与行动不便人群。**

它用 Jetson 边缘设备和摄像头感知人行无障碍空间中的盲道占用、台阶、坡道和路面障碍，把视觉检测结果压缩成简短、明确、可执行的语音提示，帮助用户判断"眼前这一步怎么安全通过"。

一句话对比：

> 无人驾驶让车看懂路，LinkAble 让弱势行人听懂路。

当前研电赛版本重点验证：

```
视觉感知 → 事件理解 → 本地语音提示 → 结构化记录
```

## 1. 应用价值

### 1.1 填补"最后几米"的空白

现有导航 App 解决"从 A 走到 B"，盲杖只能探测 1 米内有无障碍物，均无法回答"眼前这一步是什么、怎么应对"。LinkAble 填补此空白：识别障碍类型，给出可执行提示。

### 1.2 让无障碍环境问题变可见

结构化事件记录（时间、位置、类型、置信度）天然形成无障碍环境巡检数据，可沉淀为校园/社区无障碍治理的量化依据。

### 1.3 低成本可部署

单摄像头 + Jetson 边缘推理，无需改造基础设施，支持可穿戴、手持巡检、固定点位三种部署形态，共享同一套感知、事件和播报代码。

### 1.4 安全边界声明

系统定位为"辅助提示"，不替代盲杖、导盲犬或用户自主判断，不直接控制用户行动。

## 4. 系统架构

### 主链路

```
摄像头/图片/视频输入
  → YOLO 检测（yolo11n.pt）
  → 事件聚合与去抖（EventBuilder）
  → 模板化中文提示（semantics.py）
  → 本地音频播报（audio.py / MiniMax TTS）
  → 结构化事件记录（publisher.py）
```

### 核心原则

- 端侧优先，不依赖云端才能播报
- 音频优先使用本地缓存
- 云端和 App 是增强，不是主链路

### 推荐模块

| 模块 | 职责 |
|---|---|
| `detector.py` | YOLOv11 推理，P0 类别过滤 |
| `event_builder.py` | 连续帧去抖、冷却控制、优先级排序 |
| `semantics.py` | 事件转模板化中文提示 |
| `audio.py` | 本地 mp3 播报、失败降级 |
| `pipeline.py` | 串联完整主链路 |
| `publisher.py` | 可选 HTTP 上报结构化事件 |
| `usb_demo.py` | 主演示入口 |

### 部署形态

| 形态 | 当前定位 |
|---|---|
| 胸前/肩带式短距离佩戴 | 演示形态，适合拍摄靠近障碍的视频 |
| 手持/推车式巡检 | 推荐主形态，适合校园无障碍环境巡检 |
| 固定点位监测 | 备用形态，适合盲道/坡道入口固定场景 |

## 5. P0 功能范围

### 5.1 P0 必做

| 功能 | 验收标准 |
|---|---|
| 盲道占用检测（`blind_road_occupied`） | 典型场景可稳定触发 |
| 台阶识别（`stairs`） | 能播报减速/注意提示 |
| 坡道识别（`ramp`） | 能给出坡道存在或方位提示 |
| 路面障碍检测（`road_obstacle`） | 能触发避让提示 |
| 事件聚合与去抖 | 同一障碍不连续刷屏 |
| 模板化语义提示 | 输出 <50 字中文短句，明确可执行 |
| 本地音频播报 | 不依赖云端即可演示 |
| 结构化事件记录 | 含 node_id、timestamp、type、confidence |

### 5.2 P1 增强（P0 稳定后推进）

检测结果上报 FastAPI、云端语义增强、Flutter 展示页、主动语音查询、红绿灯识别、人行横道识别

### 5.3 P2 本期不做

志愿者互助系统、多用户并发平台、量产级硬件外壳

## 6. P0 事件类别

| 类别 | 英文名 | 优先级 | 说明 |
|---|---|---|---|
| 台阶 | `stairs` | 100 | 最高优先级，安全风险最高 |
| 路面障碍 | `road_obstacle` | 80 | 锥桶、箱子、围挡、杂物等临时障碍 |
| 盲道占用 | `blind_road_occupied` | 70 | 盲道被单车、箱子、围挡占用 |
| 坡道 | `ramp` | 60 | 无障碍坡道、缓坡入口 |

P1 预留（当前不训练）：`traffic_red`、`traffic_green`、`crosswalk`

## 7. 语音播报策略

### 默认音色

```
model = speech-2.8-hd
voice_id = presenter_female
```

### 播报原则

- 句子短，优先 <50 字
- 必须包含风险类型
- 有条件时包含距离或方向
- 避免"可能、似乎、也许"等不确定措辞
- 不连续重复播报同一障碍

### 推荐文案

```
前方盲道被占用，请注意绕行。
前方有台阶，请减速。
右前方有障碍，请注意避让。
前方有坡道，位于右侧。
```

### 降级策略

| 问题 | 降级 |
|---|---|
| MiniMax 网络不可用 | 使用本地缓存 mp3 |
| mp3 缺失 | 终端文字输出 |
| 音频设备异常 | 显示字幕/日志 |
| 同一事件重复触发 | 冷却时间内不播报 |

## 8. 数据与模型

### 数据采集目标

```
>=600 张有效图像
```

推荐分布：

| 场景 | 占比 |
|---|---:|
| 盲道占用 | 35% |
| 台阶 | 20% |
| 坡道 | 20% |
| 路面障碍 | 25% |

### 模型路线

```
yolo11n PyTorch → ONNX → TensorRT FP16
```

阶段性止损：

- 自定义模型未完成时，用 COCO 代理类演示完整链路
- TensorRT 未完成时，用 PyTorch/Ultralytics 先证明功能闭环
- 摄像头未恢复时，用图片序列或视频文件模拟移动场景

## 9. 性能与验收指标

| 指标 | 目标 |
|---|---|
| Jetson 端推理帧率 | ≥30 FPS |
| 单帧推理延迟 | <100 ms |
| 检测到播报响应 | <1.5 s |
| 主要场景准确率 | ≥80% |
| 同一障碍重复播报 | 冷却时间内不重复 |
| 离线演示能力 | 云端不可用时仍可播报 |

### 论文/答辩必须量化

- FPS、单帧推理延迟
- 检测到播报延迟
- TTS 冷启动与缓存命中延迟
- 典型场景识别成功率
- 数据集规模和类别分布
- 演示场景实测记录

## 13. 对外口径

### 30 秒介绍

LinkAble 是一套基于边缘智能的无障碍辅助通行感知系统。系统通过 Jetson 和摄像头感知人行空间中的盲道占用、台阶、坡道和路面障碍，在端侧完成事件聚合和本地语音播报。相比自动驾驶关注车辆行驶，LinkAble 关注弱势行人眼前几米的安全通行，把视觉检测结果转化为简短、明确、可执行的语音提示。

### 展架主标题

```
从"车能自己开"到"人能安全走"
```

### 展架副标题

```
基于边缘智能的无障碍辅助通行感知系统
```

### 核心卖点

- 面向人行无障碍空间，而非机动车道
- 单摄像头 + Jetson 边缘推理，低成本可部署
- 检测结果转语音提示，用户可直接执行
- 支持可穿戴、手持巡检、固定点位多种形态
- 结构化事件可沉淀为无障碍治理数据

### 禁止说的

- "已经做出了成熟导盲设备"
- "可以替代盲杖或导盲犬"
- "可以保证视障用户完全安全"
- "核心是 App/云平台/志愿者系统"
