## 0. 一句話定義

**LinkAble 是一套基於邊緣智能的無障礙輔助通行感知系統，部署於人行無障礙空間的關鍵節點，實時識別盲道佔用、臺階、坡道、路面障礙等通行風險，通過語音播報爲視障與行動不便人羣提供即時通行提示，同時沉澱結構化事件數據支撐無障礙環境治理。**

一句話對比：

> 無人駕駛讓車看懂路，LinkAble 讓弱勢行人聽懂路、讓管理者看見盲區。

## 1. 項目本質與邊界（必讀）

### 1.1 這是什麼

LinkAble 是一個**邊緣智能感知原型系統**，不是一款穿戴式導盲產品。它的技術內核是：

```
視覺感知 → 事件理解 → 本地語音提示 → 結構化記錄
```

### 1.2 這不是什麼

- ❌ 不是成熟的穿戴式導盲硬件
- ❌ 不能替代盲杖、導盲犬或用戶自主判斷
- ❌ 不直接控制用戶行動，不承擔安全責任
- ❌ 不是手機 App，不是雲平臺，不是志願者系統

### 1.3 爲什麼這樣定位

Jetson Orin Nano 需要持續供電與散熱，長期穿戴在視障用戶身上不現實，且開放道路場景的安全責任邊界過重。本項目的合理形態是**部署在固定節點或用於巡檢的邊緣感知設備**，而非穿戴式產品。

穿戴形態僅作爲**演示形態**保留，用於拍攝"用戶靠近障礙並聽到提示"的視頻片段，不構成產品主線。

## 2. 應用價值

### 2.1 讓無障礙環境的隱性問題變可見（核心）

盲道被共享單車佔用、坡道入口堆放雜物、路面臨時障礙——這些問題在城市管理者視角是隱性的，缺乏系統化的數據支撐。LinkAble 通過結構化事件記錄（時間、位置、類型、置信度），把這些隱性問題轉化爲可量化、可追溯、可治理的數據。

**這是項目最有可能真正落地的價值。**

### 2.2 填補"最後幾米"的輔助提示空白

現有導航 App 解決"從 A 走到 B"，盲杖只能探測 1 米內有無障礙物，均無法回答"眼前這一步是什麼、怎麼應對"。LinkAble 在固定節點提供局部通行風險的實時提示，填補這一空白。

### 2.3 低成本可部署的邊緣智能骨架

單攝像頭 + Jetson 邊緣推理，無需改造基礎設施。技術骨架可遷移至工廠巡檢、園區安防、設施監測等需要"實時識別 + 即時響應"的場景。

## 5. 系統架構

### 5.1 主鏈路（邊緣端，實時）

```
攝像頭/圖片/視頻輸入
  → YOLO 檢測（yolo11n.pt）
  → 事件聚合與去抖（EventBuilder）
  → 模板化中文提示（semantics.py）
  → 本地音頻播報（audio.py / MiniMax TTS）
  → 結構化事件記錄（publisher.py）
```

### 5.2 增強鏈路（雲端，離線，P1）

```
結構化事件流（JSON）
  → 大模型分析（Kimi/Qwen）
  → 周/月度無障礙報告
  → 治理建議輸出
```

> 大模型僅用於離線分析報告生成，**不進入實時避障鏈路**，避免引入網絡延遲和不確定性。

### 5.3 設計原則

- **端側實時優先**：實時避障鏈路全部在邊緣完成，<1.5 秒響應
- **本地音頻緩存**：演示現場不依賴雲端 TTS
- **大模型離線增強**：雲端用於事後數據分析，不影響實時性
- **規則系統兜底**：所有關鍵決策由確定性規則做出，LLM 不參與安全相關決策

### 5.4 推薦模塊

| 模塊 | 職責 |
|---|---|
| `detector.py` | YOLOv11 推理，P0 類別過濾 |
| `event_builder.py` | 連續幀去抖、冷卻控制、優先級排序 |
| `semantics.py` | 事件轉模板化中文提示 |
| `audio.py` | 本地 mp3 播報、失敗降級 |
| `pipeline.py` | 串聯完整主鏈路 |
| `publisher.py` | 可選 HTTP 上報結構化事件 |
| `usb_demo.py` | 主演示入口 |
| `report_gen.py`（P1） | 離線事件流 → LLM → 報告 |

### 5.5 部署形態（已重新排序）

| 形態 | 當前定位 | 應用場景 |
|---|---|---|
| **固定點位部署** | **推薦主形態** | 盲道入口、坡道入口、樓宇門口、地鐵口 |
| **手持/推車式巡檢** | 推薦主形態 | 校園、社區無障礙環境週期性巡檢 |
| 短距離佩戴 | **演示形態** | 僅用於拍攝演示視頻片段 |

> 形態排序對齊項目真實價值：固定部署和巡檢是落地形態，穿戴只是演示道具。

## 8. 語音播報策略

### 默認音色

```
model = speech-2.8-hd
voice_id = presenter_female
```

### 播報原則

- 句子短，優先 <50 字
- 必須包含風險類型
- 有條件時包含距離或方向
- 避免"可能、似乎、也許"等不確定措辭
- 不連續重複播報同一障礙
- **信息密度低、決策清晰**——視障輔助的黃金原則

### 推薦文案

```
前方盲道被佔用，請注意繞行。
前方有臺階，請減速。
右前方有障礙，請注意避讓。
前方有坡道，位於右側。
```

### 降級策略

| 問題 | 降級 |
|---|---|
| MiniMax 網絡不可用 | 使用本地緩存 mp3 |
| mp3 缺失 | 終端文字輸出 |
| 音頻設備異常 | 顯示字幕/日誌 |
| 同一事件重複觸發 | 冷卻時間內不播報 |

## 15. 對外口徑

### 30 秒介紹

LinkAble 是一套基於邊緣智能的無障礙輔助通行感知系統。系統通過 Jetson 和攝像頭部署在人行無障礙空間的關鍵節點，實時感知盲道佔用、臺階、坡道和路面障礙，在端側完成事件聚合和本地語音播報。相比自動駕駛關注車輛行駛，LinkAble 關注弱勢行人眼前幾米的安全通行；相比傳統盲杖只能物理探測，LinkAble 能識別障礙類型並語義化提示；相比 App 只能宏觀導航，LinkAble 能感知局部環境並即時反饋。同時，結構化事件數據可沉澱爲無障礙環境治理的量化依據。

### 展架主標題

```
從"車能自己開"到"人能安全走"
```

### 展架副標題

```
基於邊緣智能的無障礙輔助通行感知系統
```

### 核心賣點

- 面向人行無障礙空間，而非機動車道
- 單攝像頭 + Jetson 邊緣推理，低成本可部署
- 檢測結果轉語義化中文播報，用戶可直接執行
- 結構化事件數據沉澱爲無障礙治理依據
- 邊緣實時 + 雲端離線大模型分析的雙鏈路架構

### 應對常見質疑的標準答案

**Q：怎麼戴在盲人身上？**
> A：當前版本是邊緣智能原型系統，主要部署形態是固定節點和手持巡檢，不是穿戴式產品。穿戴形態僅作爲演示場景。穿戴化是後續輕量化硬件設計的工作方向。

**Q：和盲杖/導盲犬比有什麼優勢？**
> A：盲杖只能物理探測 1 米內的存在，不識別類型；導盲犬成本高、稀缺；LinkAble 識別障礙類別並語義化播報，且數據可沉澱爲治理依據。三者不是替代關係而是互補。

**Q：爲什麼不直接用大模型？**
> A：實時避障鏈路對延遲敏感（<1.5秒），大模型推理延遲（3-5秒）會破壞實時性。我們將大模型用於離線事件流分析與無障礙報告生成，發揮其語義理解能力，而不引入實時性風險。

### 禁止說的

- "已經做出了成熟導盲設備"
- "可以替代盲杖或導盲犬"
- "可以保證視障用戶完全安全"
- "核心是 App/雲平臺/志願者系統"
