## 1. 功能清單

### F1: 智能對話

| 屬性 | 詳情 |
|------|------|
| **優先級** | P0 |
| **核心用戶故事** | 作爲求助者，我用語音/文字/拍照描述問題，AI 能理解我的意圖並直接給出解答 |
| **技術方案** | NLP意圖識別 + 多模態輸入處理 + 緊急度判斷算法 |
| **驗收標準** | 1. 支持語音/文字/拍照三種輸入方式<br>2. 意圖識別準確率 ≥ 85%<br>3. 首次響應 ≤ 3秒<br>4. 正確區分AI可處理/需轉人工的場景 |

**意圖分類處理表：**

| 意圖類別 | AI處理 | 轉人工條件 |
|---------|--------|-----------|
| 文字識別 | ✅ OCR+TTS | 識別失敗時 |
| 物體識別 | ✅ 多模態視覺 | 複雜場景 |
| 顏色識別 | ✅ 顏色檢測 | — |
| 鈔票識別 | ✅ 面額識別 | — |
| 翻譯 | ✅ OCR+翻譯 | — |
| 導航 | ✅ 地圖API | 室內複雜導航 |
| 環境描述 | ✅ 場景描述 | 需要精確指引時 |
| 藥品確認 | ⚠️ AI初篩 | ✅ 必須轉人工確認 |
| 醫療問診 | ❌ | ✅ 匹配醫療背景志願者 |
| 情感陪伴 | ⚠️ AI初步回應 | ✅ 優先匹配心理支持志願者 |
| 緊急求助 | ❌ | ✅ 觸發SOS流程 |

### F2: OCR 文字識別與朗讀

| 屬性 | 詳情 |
|------|------|
| **優先級** | P0 |
| **核心用戶故事** | 作爲視障用戶，我拍照後能聽到圖片中的文字內容 |
| **技術方案** | 百度OCR API（在線）/ PaddleOCR Lite（離線備選） |
| **驗收標準** | 1. 支持印刷體、手寫體（中/英）、豎排文字<br>2. 識別準確率 ≥ 90%<br>3. 支持藥品標籤、快遞單等小字場景<br>4. 離線模式基礎功能可用 |

## 3. 技術實現要點

### 3.1 核心技術點彙總

| 功能 | 核心技術點 | 離線/在線 | 性能要求 |
|------|-----------|----------|---------|
| F1 智能對話 | NLP意圖識別、多輪對話管理、緊急度分類 | 混合 | 首次響應 ≤ 3秒 |
| F2 OCR | 文字檢測、OCR識別、TTS朗讀 | 混合 | 識別+朗讀 ≤ 5秒 |
| F3 物體識別 | 多模態大模型調用、結構化輸出解析 | 在線 | 響應 ≤ 5秒 |
| F4 顏色識別 | 圖像顏色提取、顏色空間轉換、色盲友好命名 | 離線 | 響應 ≤ 2秒 |
| F5 鈔票識別 | 圖像分類、幣種檢測、面額識別 | 離線 | 響應 ≤ 2秒 |
| F6 翻譯 | OCR+機器翻譯+TTS流水線 | 在線 | 響應 ≤ 5秒 |
| F7 環境描述 | 多模態大模型、空間關係理解 | 在線 | 響應 ≤ 5秒 |
| F8 緊急檢測 | 關鍵詞匹配、語音情緒分析、二次確認機制 | 離線 | 實時檢測 |

### 3.2 關鍵技術挑戰

#### 挑戰1：多模態輸入的統一處理
- **問題**：語音、文字、拍照三種輸入方式需要統一處理流程
- **方案**：F1作爲統一入口，根據輸入類型分發到對應處理模塊

#### 挑戰2：離線/在線模式切換
- **問題**：網絡不穩定時需要降級到離線模式
- **方案**：
  - 優先嚐試在線API（精度高）
  - 超時後自動切換離線模型
  - 用戶可手動選擇離線模式

#### 挑戰3：大模型API成本控制
- **問題**：多模態大模型調用成本較高
- **方案**：
  - 簡單任務（顏色/鈔票）用本地模型
  - 複雜任務（場景描述）才調用大模型
  - 緩存常見查詢結果

#### 挑戰4：緊急檢測的準確性與時效性
- **問題**：需要實時檢測且避免誤報
- **方案**：
  - 本地關鍵詞庫實時匹配
  - 二次確認機制（彈窗+倒計時）
  - 持續優化觸發詞庫

## 5. 風險點

### 5.1 技術風險

| 風險 | 等級 | 影響 | 緩解措施 |
|------|------|------|---------|
| 多模態大模型API不穩定 | 高 | F3/F7功能不可用 | 1. 實現超時降級機制<br>2. 準備備用模型（Kimi/通義切換）<br>3. MVP階段簡化描述需求 |
| OCR識別準確率不足 | 中 | 用戶體驗差 | 1. 百度OCR+本地Paddle雙保險<br>2. 針對藥品標籤等場景優化<br>3. 提供重新拍照功能 |
| 意圖識別誤判 | 中 | 該轉人工的沒轉 | 1. 保守策略：不確定時轉人工<br>2. 用戶反饋閉環優化<br>3. 醫療/情感場景強制轉人工 |
| 離線模型體積過大 | 中 | App包體積超標 | 1. 按需下載模型<br>2. 壓縮模型精度<br>3. 僅核心功能離線化 |

### 5.2 識別誤報風險

| 風險場景 | 說明 | 緩解措施 |
|---------|------|---------|
| F8 緊急詞誤觸發 | 用戶正常對話中包含"救命"等詞彙 | 1. 上下文分析<br>2. 二次確認彈窗<br>3. 5秒倒計時取消機制 |
| F2 OCR 誤讀 | 藥品標籤識別錯誤導致用藥風險 | 1. 藥品場景強制轉人工確認<br>2. 置信度低時提示用戶<br>3. 免責聲明 |
| F3/F7 場景描述錯誤 | 物體位置描述錯誤導致用戶碰撞 | 1. 距離描述加模糊詞（約、大概）<br>2. 提醒用戶謹慎行動<br>3. 複雜場景轉人工 |
| F5 鈔票識別錯誤 | 面額識別錯誤導致經濟損失 | 1. 高置信度閾值<br>2. 多次驗證<br>3. 提示用戶二次確認 |

### 5.3 外部依賴風險

| 風險 | 說明 | 緩解措施 |
|------|------|---------|
| 百度OCR服務限制 | 免費額度用盡或服務調整 | 1. 監控API調用量<br>2. 準備PaddleOCR備用方案<br>3. 考慮付費升級 |
| 通義千問VL/Kimi API變更 | 接口變更或價格上漲 | 1. 抽象AI服務層<br>2. 支持多模型切換<br>3. 本地緩存策略 |
| 網絡環境差 | 在線功能無法使用 | 1. 離線模式設計<br>2. 弱網提示<br>3. 核心功能離線化 |

### 5.4 安全風險

| 風險 | 說明 | 緩解措施 |
|------|------|---------|
| AI生成內容不當 | 場景描述包含不當內容 | 1. 內容安全過濾<br>2. 敏感場景人工審覈<br>3. 用戶舉報機制 |
| 隱私數據泄露 | 圖片/語音數據在傳輸中泄露 | 1. HTTPS傳輸<br>2. 數據最小化原則<br>3. 7天自動刪除 |
| 緊急檢測失效 | 真實緊急情況未觸發SOS | 1. 手動SOS按鈕兜底<br>2. 多種觸發方式<br>3. 定期測試驗證 |

## 6. 總結與建議

### 6.1 關鍵結論

1. **F1智能對話是核心樞紐**：需要優先實現，作爲所有AI能力的統一入口
2. **離線能力至關重要**：F4顏色識別、F5鈔票識別、F8緊急檢測必須支持離線
3. **醫療/安全場景保守處理**：藥品確認、緊急求助必須轉人工或二次確認
4. **MVP範圍可控**：P0功能聚焦核心識別能力，P1功能可延後

### 6.2 實施建議

1. **第一週**：搭建F1框架 + F2 OCR + F4顏色識別
2. **第二週**：集成通義千問VL實現F3/F7 + F8緊急檢測
3. **第三週**：聯調優化 + 意圖識別準確率提升
4. **第四周**：離線模式完善 + Bug修復

### 6.3 需要重點關注的問題

- [ ] 多模態大模型API的穩定性與成本控制
- [ ] 緊急檢測的誤報率控制
- [ ] 離線模型的包體積優化
- [ ] 醫療/安全場景的人工兜底機制
