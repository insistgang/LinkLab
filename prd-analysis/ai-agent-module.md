## 1. 功能清单

### F1: 智能对话

| 属性 | 详情 |
|------|------|
| **优先级** | P0 |
| **核心用户故事** | 作为求助者，我用语音/文字/拍照描述问题，AI 能理解我的意图并直接给出解答 |
| **技术方案** | NLP意图识别 + 多模态输入处理 + 紧急度判断算法 |
| **验收标准** | 1. 支持语音/文字/拍照三种输入方式<br>2. 意图识别准确率 ≥ 85%<br>3. 首次响应 ≤ 3秒<br>4. 正确区分AI可处理/需转人工的场景 |

**意图分类处理表：**

| 意图类别 | AI处理 | 转人工条件 |
|---------|--------|-----------|
| 文字识别 | ✅ OCR+TTS | 识别失败时 |
| 物体识别 | ✅ 多模态视觉 | 复杂场景 |
| 颜色识别 | ✅ 颜色检测 | — |
| 钞票识别 | ✅ 面额识别 | — |
| 翻译 | ✅ OCR+翻译 | — |
| 导航 | ✅ 地图API | 室内复杂导航 |
| 环境描述 | ✅ 场景描述 | 需要精确指引时 |
| 药品确认 | ⚠️ AI初筛 | ✅ 必须转人工确认 |
| 医疗问诊 | ❌ | ✅ 匹配医疗背景志愿者 |
| 情感陪伴 | ⚠️ AI初步回应 | ✅ 优先匹配心理支持志愿者 |
| 紧急求助 | ❌ | ✅ 触发SOS流程 |

### F2: OCR 文字识别与朗读

| 属性 | 详情 |
|------|------|
| **优先级** | P0 |
| **核心用户故事** | 作为视障用户，我拍照后能听到图片中的文字内容 |
| **技术方案** | 百度OCR API（在线）/ PaddleOCR Lite（离线备选） |
| **验收标准** | 1. 支持印刷体、手写体（中/英）、竖排文字<br>2. 识别准确率 ≥ 90%<br>3. 支持药品标签、快递单等小字场景<br>4. 离线模式基础功能可用 |

### F3: 物体/场景识别与描述

| 属性 | 详情 |
|------|------|
| **优先级** | P0 |
| **核心用户故事** | 作为视障用户，我拍照后能了解面前有什么物体及其相对位置 |
| **技术方案** | 通义千问VL / Kimi Vision API |
| **验收标准** | 1. 输出结构化描述（距离/方位/物体）<br>2. 支持多轮追问<br>3. 响应时间 ≤ 5秒<br>4. 描述准确率 ≥ 80% |

**输出格式示例：**
```text
前方2米有一张木桌，右侧1米有一扇门，桌上有一杯水和一本书
```

## 3. 技术实现要点

### 3.1 核心技术点汇总

| 功能 | 核心技术点 | 离线/在线 | 性能要求 |
|------|-----------|----------|---------|
| F1 智能对话 | NLP意图识别、多轮对话管理、紧急度分类 | 混合 | 首次响应 ≤ 3秒 |
| F2 OCR | 文字检测、OCR识别、TTS朗读 | 混合 | 识别+朗读 ≤ 5秒 |
| F3 物体识别 | 多模态大模型调用、结构化输出解析 | 在线 | 响应 ≤ 5秒 |
| F4 颜色识别 | 图像颜色提取、颜色空间转换、色盲友好命名 | 离线 | 响应 ≤ 2秒 |
| F5 钞票识别 | 图像分类、币种检测、面额识别 | 离线 | 响应 ≤ 2秒 |
| F6 翻译 | OCR+机器翻译+TTS流水线 | 在线 | 响应 ≤ 5秒 |
| F7 环境描述 | 多模态大模型、空间关系理解 | 在线 | 响应 ≤ 5秒 |
| F8 紧急检测 | 关键词匹配、语音情绪分析、二次确认机制 | 离线 | 实时检测 |

### 3.2 关键技术挑战

#### 挑战1：多模态输入的统一处理
- **问题**：语音、文字、拍照三种输入方式需要统一处理流程
- **方案**：F1作为统一入口，根据输入类型分发到对应处理模块

#### 挑战2：离线/在线模式切换
- **问题**：网络不稳定时需要降级到离线模式
- **方案**：
  - 优先尝试在线API（精度高）
  - 超时后自动切换离线模型
  - 用户可手动选择离线模式

#### 挑战3：大模型API成本控制
- **问题**：多模态大模型调用成本较高
- **方案**：
  - 简单任务（颜色/钞票）用本地模型
  - 复杂任务（场景描述）才调用大模型
  - 缓存常见查询结果

#### 挑战4：紧急检测的准确性与时效性
- **问题**：需要实时检测且避免误报
- **方案**：
  - 本地关键词库实时匹配
  - 二次确认机制（弹窗+倒计时）
  - 持续优化触发词库

## 5. 风险点

### 5.1 技术风险

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|---------|
| 多模态大模型API不稳定 | 高 | F3/F7功能不可用 | 1. 实现超时降级机制<br>2. 准备备用模型（Kimi/通义切换）<br>3. MVP阶段简化描述需求 |
| OCR识别准确率不足 | 中 | 用户体验差 | 1. 百度OCR+本地Paddle双保险<br>2. 针对药品标签等场景优化<br>3. 提供重新拍照功能 |
| 意图识别误判 | 中 | 该转人工的没转 | 1. 保守策略：不确定时转人工<br>2. 用户反馈闭环优化<br>3. 医疗/情感场景强制转人工 |
| 离线模型体积过大 | 中 | App包体积超标 | 1. 按需下载模型<br>2. 压缩模型精度<br>3. 仅核心功能离线化 |

### 5.2 识别误报风险

| 风险场景 | 说明 | 缓解措施 |
|---------|------|---------|
| F8 紧急词误触发 | 用户正常对话中包含"救命"等词汇 | 1. 上下文分析<br>2. 二次确认弹窗<br>3. 5秒倒计时取消机制 |
| F2 OCR 误读 | 药品标签识别错误导致用药风险 | 1. 药品场景强制转人工确认<br>2. 置信度低时提示用户<br>3. 免责声明 |
| F3/F7 场景描述错误 | 物体位置描述错误导致用户碰撞 | 1. 距离描述加模糊词（约、大概）<br>2. 提醒用户谨慎行动<br>3. 复杂场景转人工 |
| F5 钞票识别错误 | 面额识别错误导致经济损失 | 1. 高置信度阈值<br>2. 多次验证<br>3. 提示用户二次确认 |

### 5.3 外部依赖风险

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| 百度OCR服务限制 | 免费额度用尽或服务调整 | 1. 监控API调用量<br>2. 准备PaddleOCR备用方案<br>3. 考虑付费升级 |
| 通义千问VL/Kimi API变更 | 接口变更或价格上涨 | 1. 抽象AI服务层<br>2. 支持多模型切换<br>3. 本地缓存策略 |
| 网络环境差 | 在线功能无法使用 | 1. 离线模式设计<br>2. 弱网提示<br>3. 核心功能离线化 |

### 5.4 安全风险

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| AI生成内容不当 | 场景描述包含不当内容 | 1. 内容安全过滤<br>2. 敏感场景人工审核<br>3. 用户举报机制 |
| 隐私数据泄露 | 图片/语音数据在传输中泄露 | 1. HTTPS传输<br>2. 数据最小化原则<br>3. 7天自动删除 |
| 紧急检测失效 | 真实紧急情况未触发SOS | 1. 手动SOS按钮兜底<br>2. 多种触发方式<br>3. 定期测试验证 |

## 6. 总结与建议

### 6.1 关键结论

1. **F1智能对话是核心枢纽**：需要优先实现，作为所有AI能力的统一入口
2. **离线能力至关重要**：F4颜色识别、F5钞票识别、F8紧急检测必须支持离线
3. **医疗/安全场景保守处理**：药品确认、紧急求助必须转人工或二次确认
4. **MVP范围可控**：P0功能聚焦核心识别能力，P1功能可延后

### 6.2 实施建议

1. **第一周**：搭建F1框架 + F2 OCR + F4颜色识别
2. **第二周**：集成通义千问VL实现F3/F7 + F8紧急检测
3. **第三周**：联调优化 + 意图识别准确率提升
4. **第四周**：离线模式完善 + Bug修复

### 6.3 需要重点关注的问题

- [ ] 多模态大模型API的稳定性与成本控制
- [ ] 紧急检测的误报率控制
- [ ] 离线模型的包体积优化
- [ ] 医疗/安全场景的人工兜底机制
