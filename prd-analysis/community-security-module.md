## 2. 安全体系设计

### 2.1 F28: 多级认证体系详细流程

#### 认证层级表

| 用户类型 | 认证等级 | 认证方式 | 获得权益 |
|----------|----------|----------|----------|
| 求助者（残障） | 基础认证 | 手机号 + 实名 | 基础求助功能 |
| 求助者（残障） | 优先认证 | + 残疾证/盲协证明 | 优先匹配权、专属标识 |
| 求助者（普通） | 标准认证 | 手机号 + 实名 | 基础求助功能 |
| 志愿者 | 基础认证 | 手机号 + 实名 + 信用分（芝麻/微信） | 基础帮助功能 |
| 志愿者 | 认证技能 | + 专业证明上传 + 人工审核 | 技能标签展示、高权重匹配 |

#### 认证流程图

```text
注册 → 手机号验证 → 身份选择（求助者/志愿者）
    ↓
求助者路径：
    ├── 基础信息填写（障碍类型、偏好设置）
    ├── 可选：上传残障证明 → 人工审核（48h）→ 获得优先标识
    └── 完成

志愿者路径：
    ├── 基础信息填写
    ├── 第三方信用授权（芝麻/微信信用分）
    ├── 选择技能标签
    ├── 需认证技能？→ 上传证明文件 → 人工审核
    └── 完成
```

#### 技术实现要点

1. **证件审核**：OCR识别证件信息 + 人工复核
2. **信用接入**：支付宝芝麻信用/微信信用分API对接
3. **审核时效**：承诺48小时内完成审核
4. **状态管理**：认证状态实时同步到用户资料

### 2.2 F29: 录音与内容检测方案

#### 录音方案

| 项目 | 设计 |
|------|------|
| **默认状态** | 默认开启 |
| **用户控制** | 可在F17偏好设置中关闭 |
| **存储时长** | 7天自动删除 |
| **存储位置** | 国内合规云存储 |
| **加密要求** | 端到端加密存储 |
| **访问权限** | 仅用于纠纷处理，需审批调取 |

#### AI内容检测方案

| 检测类型 | 触发条件 | 处理方式 |
|----------|----------|----------|
| 辱骂/人身攻击 | 实时语音转文本分析 | 自动警告 + 记录标记 |
| 敏感内容 | 涉黄/涉暴/涉政关键词 | 自动中断 + 人工复核 |
| 诈骗诱导 | 金钱交易、个人信息索取 | 实时提醒用户 + 标记上报 |
| 异常行为 | 长时间沉默、重复呼叫 | 系统提示 + 自动挂断 |

#### 技术架构

```text
通话流 → WebRTC → 实时转写（讯飞ASR）→ NLP分析
    ↓
检测到违规 → 实时警告（双方）→ 记录标记
    ↓
通话结束 → 录音文件 → 加密存储 → 7天后自动删除
```

### 2.3 F30: 双向互评与信用分算法

#### 评价流程

```text
通话结束 → 弹出评价页 → 双方互评
    ↓
求助者评价志愿者：1-5星 + 可选文字感谢
志愿者评价求助者：1-5星 + 可选标签（礼貌/恶意/骚扰）
    ↓
评价结果 → 信用分计算 → 影响后续匹配权重
```

#### 信用分算法设计

**基础分制**：5分制，新用户默认5.0分

**分数变动规则**：

| 行为 | 分数变动 | 说明 |
|------|----------|------|
| 获得5星评价 | +0.1 | 单次上限 |
| 获得4星评价 | +0.05 | 单次上限 |
| 获得3星及以下 | -0.2 | 单次上限 |
| 被有效举报 | -1.0 | 视严重程度 |
| 连续10次好评 | +0.3 | 额外奖励 |
| 30天无违规 | +0.1 | 月度奖励 |

**匹配权重影响**：

```
匹配分 = ... + w4×信誉分 + ...

信誉分权重规则：
- 4.5-5.0分：正常权重
- 4.0-4.5分：权重×0.8
- 3.5-4.0分：权重×0.5，限制匹配频率
- <3.5分：暂停匹配，需人工审核
```

### 2.4 F31: 举报处理流程

#### 举报入口

- **位置**：通话结束页、历史记录页、通话中快捷按钮
- **方式**：一键举报，选择举报原因，可选上传证据

#### 举报处理流程

```text
用户举报 → 系统记录 → 临时冻结双方匹配（24h）
    ↓
人工审核队列 → 48h内完成审核
    ↓
    ├── 举报成立 → 处理被举报人 + 通知举报人
    │       ├── 轻微违规：警告 + 信用分扣减
    │       ├── 严重违规：封号7-30天
    │       └── 恶意违规：永久封号 + 设备指纹封禁
    │
    └── 举报不成立 → 恢复匹配 + 记录标记
```

#### 黑名单机制

| 黑名单类型 | 触发条件 | 影响范围 |
|------------|----------|----------|
| 用户级 | 被多次举报核实 | 该账号永久封禁 |
| 设备级 | 同一设备多次违规 | 设备指纹封禁，该设备无法注册 |
| IP级 | 同一IP批量注册违规账号 | IP段限制注册 |

### 2.5 F32: 紧急联系人管理

#### 功能设计

| 项目 | 设计 |
|------|------|
| **设置数量** | 最多3个紧急联系人 |
| **信息字段** | 姓名、电话、关系、优先级（1-3） |
| **触发条件** | F13 SOS广播自动触发 |
| **通知方式** | 短信 + Push通知 |
| **通知内容** | 包含位置链接的求助信息 |

#### 触发流程

```text
SOS触发 → 获取精确位置（GPS+基站）
    ↓
并行通知：
    ├── 推送半径5km内所有志愿者
    ├── 发送短信给紧急联系人（含位置链接）
    └── 可选：自动拨打120/110（需用户授权）
```

## 3. 隐私保护方案

### 3.1 数据存储与加密

| 数据类型 | 存储方案 | 加密方式 | 保留期限 |
|----------|----------|----------|----------|
| 用户身份信息 | PostgreSQL | 字段级AES加密 | 账号存续期 |
| 通话录音 | 对象存储 | 端到端加密 | 7天自动删除 |
| 位置信息 | PostgreSQL（PostGIS） | 坐标偏移处理 | 求助结束后模糊化 |
| 聊天记录 | PostgreSQL | 字段级加密 | 账号存续期 |
| 评价记录 | PostgreSQL | 字段级加密 | 账号存续期 |

### 3.2 位置信息处理

#### 精度分级

| 精度级别 | 使用场景 | 误差范围 |
|----------|----------|----------|
| 精确位置 | SOS紧急求助 | <10米 |
| 模糊位置 | 普通匹配 | 100-500米 |
| 城市级 | 社群归属展示 | 仅显示城市名 |

#### 位置模糊化算法

```python
# 伪代码示例
def fuzzy_location(lat, lng, level):
    if level == 'precise':
        return (lat, lng)
    elif level == 'fuzzy':
        # 添加随机偏移
        offset_lat = random.uniform(-0.005, 0.005)
        offset_lng = random.uniform(-0.005, 0.005)
        return (lat + offset_lat, lng + offset_lng)
    elif level == 'city':
        # 返回城市中心坐标
        return get_city_center(lat, lng)
```

### 3.3 身份信息隔离

#### 隔离原则

| 场景 | 可见信息 | 隔离措施 |
|------|----------|----------|
| 匹配阶段 | 求助类型、距离、预估耗时 | 双方真实身份互不可见 |
| 通话过程中 | 系统生成的临时昵称 | 真实姓名、电话隐藏 |
| 通话结束后 | 可选显示感谢信（脱敏） | 联系方式仍不可见 |
| 常用志愿者 | 昵称 + 历史合作次数 | 需双方同意才显示更多信息 |

#### 技术实现

- 使用系统生成的UUID作为通话标识
- WebRTC通话使用临时Token，过期失效
- 真实身份信息仅存储于服务端，前端不可直接访问

## 4. 风险应对

### 4.1 PRD风险清单与应对措施

| 风险 | 影响 | 涉及的安全功能 | 具体应对措施 |
|------|------|----------------|--------------|
| **冷启动期志愿者不足** | 求助无人响应 | F13 SOS广播、F9匹配引擎 | 1. 种子用户计划（10-20名核心志愿者）<br>2. 运营团队模拟求助兜底<br>3. 高校合作招募<br>4. SOS扩大广播半径（5km→全城） |
| **AI误判紧急度** | 延误紧急求助或误触SOS | F8紧急检测、F13 SOS广播 | 1. 二次确认机制（5秒倒计时+语音确认）<br>2. 紧急词库持续优化<br>3. 用户反馈闭环训练<br>4. 手动触发SOS作为备选（连按电源键3次） |
| **隐私泄露** | 法律风险+用户流失 | F28认证、F29录音、F32紧急联系人 | 1. 端到端加密存储<br>2. 数据最小化原则<br>3. 7天自动删除录音<br>4. 定期合规审计<br>5. 用户数据导出与注销权 |
| **API成本高** | 运营不可持续 | F1智能对话、AI Agent模块 | 1. 分级调用策略（简单任务用轻量模型）<br>2. 缓存常见查询结果<br>3. 离线OCR作为备选<br>4. 异步任务错峰处理 |
| **恶意用户骚扰** | 志愿者流失+平台声誉 | F28认证、F30信用分、F31举报 | 1. 多级认证提高注册门槛<br>2. 信用分动态调节匹配权重<br>3. AI行为检测异常模式<br>4. 设备指纹封禁违规账号<br>5. 双向评价机制互相监督 |

### 4.2 额外风险识别

| 风险 | 应对策略 |
|------|----------|
| 志愿者 burnout | F23排班功能限制推送时段、F22异步任务减轻实时压力 |
| 虚假求助占用资源 | F30信用分机制、恶意求助者降权 |
| 录音数据泄露 | 端到端加密、最小权限访问、定期安全审计 |
| 位置信息被追踪 | 模糊化处理、求助结束后位置数据脱敏 |

## 6. 关键设计建议

### 6.1 安全优先原则

1. **默认安全**：录音默认开启、位置默认模糊、认证默认严格
2. **最小权限**：志愿者与求助者之间信息隔离，仅展示必要信息
3. **快速响应**：举报48小时内处理、SOS 5分钟无响应自动升级

### 6.2 社群渐进策略

1. **MVP冷启动**：不依赖社群功能，专注1对1互助体验
2. **V1.0培育**：先建立核心志愿者SIG，再扩展地区社群
3. **内容运营**：精选故事作为情感纽带，新手村保证服务质量

### 6.3 技术债务预警

| 模块 | 潜在债务 | 建议 |
|------|----------|------|
| F29 录音检测 | 实时ASR成本高 | 采样检测而非全量，优先检测高风险场景 |
| F28 认证审核 | 人工审核瓶颈 | 逐步引入AI辅助审核，建立审核员培训体系 |
| F24-F25 社群 | 内容审核压力 | 接入第三方内容审核API，建立用户举报机制 |
